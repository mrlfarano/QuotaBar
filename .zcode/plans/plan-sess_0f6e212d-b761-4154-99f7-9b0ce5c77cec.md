## QuotaBar v0.8 — Claude Max + Codex quota rings with auto-discovery

**Goal:** two new built-in providers showing 5-hour + weekly usage rings exactly like the existing z.ai source, enabled automatically when their CLI credentials are found on disk.

### Endpoints (researched, to be pinned empirically with a live curl in step 1 before writing the parser)

**Claude Max** — `GET https://api.anthropic.com/api/oauth/usage`
- Headers: `Authorization: Bearer <oauthAccessToken>`, `anthropic-beta: oauth-2025-04-20`
- Response: utilization (0–100) + resets_at per limit bucket (5-hour, weekly). Exact field names pinned via live curl in step 1.
- Credential: `~/.claude/.credentials.json` → `.claudeAiOauth.accessToken` (exists on this machine, mtime Jul 20 — may be expired).

**Codex** — `GET https://chatgpt.com/backend-api/wham/usage`
- Headers: `Authorization: Bearer <access_token>`, `ChatGPT-Account-Id: <account_id>`
- Response: `rate_limit.primary_window` (5h) / `secondary_window` (weekly), each with `used_percent`, `reset_after_seconds`, `reset_at`; plus `plan_type`.
- Credential: `~/.codex/auth.json` → `tokens.access_token`, `tokens.account_id` (fresh, Aug 25).
- Refresh on 401: `POST https://auth.openai.com/oauth/token`, `grant_type=refresh_token`, `client_id=app_EMoamEEZ73f0CkXaXp7hrann`, refresh_token from our config. New tokens stored in **our** config; `~/.codex/auth.json` is never written.

### Implementation

1. **Pin response shapes**: curl both endpoints live with the real tokens (secrets never printed to artifacts), save sanitized fixtures to `testdata/claude-usage.json` + `testdata/codex-usage.json`.
2. **Config schema** (`QuotaProvider.swift`): `SourcesConfig` gains two new optional fields (old configs keep decoding): `claude: OAuthSourceConfig?` and `codex: OAuthSourceConfig?` where `OAuthSourceConfig = { enabled: Bool = true, token: String = "", refreshToken: String? = nil, accountId: String? = nil, discovered: Bool = false }`. Token resolution mirrors `resolvedToken` (env override not applicable; file fallback described below).
3. **`ClaudeSource.swift`** (id `claude`): fetch → `SourceSection` with gauges `claude-5h` + `claude-weekly` (pct = used %, resetAt from payload). Token: config token, else re-read `.credentials.json` at fetch time (Claude Code keeps it fresh when the user runs Claude). On 401/expiry: one refresh attempt via `claude.ai/api/oauth/refresh`; on failure → section error "run `claude` once to refresh".
4. **`CodexSource.swift`** (id `codex`): fetch → `SourceSection` with `codex-5h` + `codex-weekly`. 401 → silent refresh via auth.openai.com, retry once, persist new token+expiry to our config.
5. **`Discovery.swift`**: scan at launch (before first rebuild) and via a new **"Discover Sources"** menu item. Finds: `~/.claude/.credentials.json` (claude), `~/.codex/auth.json` (codex), `GH_TOKEN`/`GITHUB_TOKEN` env (token for the existing GitHub source). For a provider with no existing config entry (or empty token) and `enabled != false`, write the credential into `~/.quotabar/config.json` (0600, already enforced), mark `discovered: true`, save, rebuild. Never overwrites a token you set manually; `enabled: false` disables discovery for that source permanently.
6. **Wire-up in `main.swift`**: section order zai → github → claude → codex → customs; the "Status Bar Source:" radio list already iterates healthy section ids so claude/codex become selectable with no extra code. Fallback chain unchanged.
7. **Offline checks** following the existing `--parse` pattern: `--parse-claude payload.json` and `--parse-codex payload.json` (run the section parser on a fixture, print gauges, exit code = pass/fail). Plus `--probe claude` / `--probe codex` for one-shot live checks.
8. **README**: new Providers section (Claude Max, Codex), auto-discovery behavior, refresh/expiry behavior, security note (tokens copied into `~/.quotabar/config.json`, 0600; CLI files never modified).

### Verification gates
- `swift build -c release` clean; offline `--parse-claude`/`--parse-codex` on fixtures produce exact expected gauge lines.
- Live: `--probe claude` and `--probe codex` print real gauges from this machine's tokens (the true end-to-end evidence).
- Discovery: delete-style test on a copy of config → scan re-adds `claude`/`codex` entries marked `discovered: true`; manually-set tokens are not touched.
- Old-config relaunch: existing `~/.quotabar/config.json` still decodes; zai snapshot unaffected.
- Reinstall via `scripts/install-login.sh`; verify new agent runs and (if claude/codex picked as mainSource) rings render.

### Out of scope (deferred)
- Official cost APIs (Anthropic Admin cost_report, OpenAI org costs, OpenRouter) — follow-up version.
- Keychain-based credential reading (per your choice; `.credentials.json` file exists so keychain isn't needed here).
- Remaining unknowns are the two response payloads' exact field names — step 1 pins them; if either endpoint rejects our token outright, that source ships as error-state-only and I'll report it rather than fake it.

### Risks
- Both endpoints are reverse-engineered/unofficial and can change without notice (same trade-off as the existing z.ai source, per your choice).
- The Claude credentials file is ~5 weeks old; the access token may need the refresh flow to work. If refresh fails, the menu shows a clear actionable error.
- Per-source gauges have no used/total token counts (percent-only payloads), so detail rows show reset countdown only — rings and percentages render as usual.
